# Homepage Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution method (chosen by the owner):** subagent-driven. Dispatch every implementer and reviewer subagent with `model: "sonnet"`.

**Goal:** Replace the Google Sites homepage with a Jekyll site in this repo. It is deployed to GitHub Pages by Actions, and students edit it through PRs.

**Architecture:**
- **Pages:** one Markdown file per page. Structured lists (news, lab members, research highlights) live in front matter and are rendered by includes.
- **Validation:** a small Jekyll plugin checks that front matter at build time, so a bad student edit fails the build with a readable message.
- **Publications:** rendered at build time from a `.bib` by `jekyll-scholar`, with a dependency-free JS filter on top.
- **Single check:** one Rake task, `bundle exec rake check`, runs the build, `htmlproofer`, Ruby tests, and JS tests. Locally and in CI it is the same command.

**Tech Stack:** Ruby 3.3, Jekyll 4.3, jekyll-scholar 7.x, html-proofer 5.x, Minitest + Nokogiri, vanilla ES modules tested with `node --test`, GitHub Actions (`actions/configure-pages`, `upload-pages-artifact`, `deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-10-22-homepage-design.md`

## Global Constraints

- English only. No Hebrew text anywhere.
- Navigation order, exactly: Home, Biography, Research, Lab, Publications, Grants & Awards.
- Footer text: `© Achiya Elyasaf since 2019`.
- Social links: Twitter `https://twitter.com/eggsterino`, LinkedIn `https://www.linkedin.com/in/achiyae/`, ORCID `https://orcid.org/0000-0002-4009-5353`, Google Scholar `https://scholar.google.co.il/citations?hl=en&user=EBx5rKoAAAAJ`, dblp `https://dblp.uni-trier.de/pers/hd/e/Elyasaf:Achiya`. They are defined once, in `_config.yml`.
- Every internal URL in a template goes through `relative_url`. The site must work both at `/homepage/` (before the DNS cutover) and at `/`.
- No runtime JS or CSS from CDNs. Only Google Fonts may be loaded externally.
- Lab photos: `assets/img/lab/<first>-<last>.jpg`, at most 400×400, under 300 KB.
- `_bibliography/publications.bib` is a byte-for-byte copy of `achiyae/bibliography/ElyasafPublications.bib`. Never push to `achiyae/bibliography`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Implementation runs on native Windows, in PowerShell. No WSL, and no Git Bash scripts.**
  - Every command the implementer runs is written for PowerShell. Project tooling must be cross-platform Ruby (Rake) or Node, so the same commands also run on Linux CI.
  - Don't use bash-only syntax (`&&`, `$(...)`, `wc`, `base64`) or macOS-only tools (`sips`, `brew`). Separate commands with `;` or run them one at a time.
  - Don't use `>` to write files: Windows PowerShell 5.1 writes UTF-16. Use `-OutFile`, `Set-Content -Encoding utf8NoBOM`, or `[IO.File]::WriteAllBytes`.
- **Toolchain** (install with `winget`):
  - Ruby+Devkit 3.3 from RubyInstaller (`winget install RubyInstallerTeam.RubyWithDevKit.3.3`, then `ridk install` and pick option 3, the MSYS2 and MINGW toolchain)
  - Node.js LTS (`winget install OpenJS.NodeJS.LTS`)
  - GitHub CLI (`winget install GitHub.cli`)
  - ImageMagick (`winget install ImageMagick.ImageMagick`)
  - Open a new PowerShell window after installing, so `PATH` updates.
- Image resizing uses ImageMagick 7 (`magick`). `magick in.jpg -resize '400x400>' -strip -quality 80 out.jpg` fits the image within 400×400 without upscaling. Use `800x800>` for the profile and research images.
- Downloads: use `Invoke-WebRequest <url> -OutFile <path>`. The old Google Sites pages and images are public.
- Line endings: `.gitattributes` forces LF on checkout. Don't commit CRLF files.

## Review Focus

1. **News dates written in different forms.** A student may write `date: 2025-03-01`, `date: "2025-03-01"`, or an invalid date. The first two must sort together correctly. An invalid one must fail the build with a message naming the item. Covered by the Task 2 plugin tests.
2. **Site served under `/homepage`.** Before the DNS cutover, every internal link and image must still resolve. Covered by the Task 1 `rake check` second build with `--baseurl /homepage` plus a test.
3. **Messy BibTeX.** This means brace-protected titles (`{{GP-Rush: ...}}`), topics written as `Behavioral Programming,Deep Learning` with no space, and entries with neither `url` nor `doi`. Expected: titles render without braces, the topic dropdown has no duplicates, and entries without a link show no "view online". Covered by Tasks 6 and 7.
4. **Lab member with missing optional fields.** A member with no photo or links still renders a clean card with initials. A member without `name` or `role` fails the build. Covered by Tasks 2 and 3.
5. **Student edits that break the build in the browser UI.** Examples: bad YAML indentation, or an image path with the wrong case (Windows and macOS are case-insensitive, Linux CI is not). Expected: the PR check fails. Covered by Task 9's deliberate-break verification and htmlproofer.

### Task 7: Publications filter (JS)

**Files:**
- Create: `assets/js/publications.js`, `test/publications.test.mjs`
- Modify: `publications.md` (load `<script type="module" src="{{ '/assets/js/publications.js' | relative_url }}">`)

**Interfaces:**
- Consumes: the Task 6 markup (`#pub-list`, `li.pub` data attributes, `section.pub-year`, `#pub-filters`).
- Produces these ES module exports:
  - `parseTopics(raw: string) -> string[]`: split on `,`, trim each part, drop empty strings, and dedupe in order.
  - `matches(entry, state) -> boolean`:
    - `entry` is `{text: string, firstAuthor: string, authors: string[], topics: string[]}`.
    - `state` is `{query: string, firstAuthor: string, author: string, topic: string}`. Empty strings mean "any".
    - Matching on `query`: lowercase it, split on whitespace, and require every term to be a substring of `entry.text.toLowerCase()`.
  - `init(doc = document) -> void`:
    - Reads the entries. `text` is the `li.textContent`, which includes the raw BibTeX in `<details>`.
    - Builds the controls inside `#pub-filters` and un-hides it:
      - `input#pub-search` with placeholder `Search publications`, and the hint `Example: journal 2022`
      - `select#pub-first-author`, `select#pub-author`, `select#pub-topic`, each with its options sorted alphabetically
      - `button#pub-reset`
    - On `input` or `change` events, sets `hidden` on each non-matching `li.pub`, and on each `section.pub-year` with no visible entries.
    - Shows `p#pub-empty` with the text "No publications match." when nothing matches.
    - Wraps everything in `try`/`catch`. On error it logs and leaves the list untouched.
  - The module auto-runs `init()` when `typeof document !== "undefined"`.

- [ ] **Step 1: Write the failing tests** in `test/publications.test.mjs` (`node:test` and `node:assert/strict`):
